## Overview

The `@vaeltrix/core` package provides zero-dependency, pure cryptographic and mathematical primitives shared across the contracts, the observer service, the REST API, and frontend applications.

## Amount scaling

Money on Stellar and in Soroban contracts is always represented as 128-bit integers (`i128` in Rust, `bigint` in TypeScript) in the asset's base units (stroops, with 7 decimal places for USDC). Never use floating-point numbers (`number`) for financial math.

```ts
export function toStroops(amountDecimal: string): bigint {
  const [whole, frac = ""] = amountDecimal.split(".");
  const paddedFrac = frac.padEnd(7, "0").slice(0, 7);
  return BigInt(whole + paddedFrac);
}

export function fromStroops(stroops: bigint): string {
  const sign = stroops < 0n ? "-" : "";
  const abs = stroops < 0n ? -stroops : stroops;
  const str = abs.toString().padStart(8, "0");
  const whole = str.slice(0, -7) || "0";
  const frac = str.slice(-7).replace(/0+$/, "");
  return frac ? `${sign}${whole}.${frac}` : `${sign}${whole}`;
}
```

- `toStroops("1000.5")` -> `10005000000n`
- `fromStroops(10005000000n)` -> `"1000.5"`

## Payment ID derivation

Each covered payment receives a globally unique, collision-resistant 32-byte hash:

```ts
export function derivePaymentId(sep31TxId: string, providerIdHex: string): string {
  const prefix = Buffer.from("VAELTRIX:PAYMENT:v1", "ascii");
  const txBytes = Buffer.from(sep31TxId, "utf8");
  const providerBytes = Buffer.from(providerIdHex, "hex");
  return createHash("sha256")
    .update(Buffer.concat([prefix, txBytes, providerBytes]))
    .digest("hex");
}
```

## Receipt verification

Completion receipts are exactly 131 bytes long, encoded with big-endian integer fields and signed with Ed25519:

```ts
export function verifyReceiptSignature(params: {
  receiptBytes: Buffer;
  publicKey: KeyObject;
  signatureHex: string;
}): boolean {
  if (params.receiptBytes.length !== 131) {
    return false;
  }
  const signature = Buffer.from(params.signatureHex, "hex");
  return verify(null, params.receiptBytes, params.publicKey, signature);
}
```

### 131-byte receipt binary layout

| Offset | Length | Field | Encoding |
| --- | --- | --- | --- |
| 0 | 19 | Domain tag | ASCII `"VAELTRIX:RECEIPT:v1"` |
| 19 | 32 | Network ID | `SHA256(network_passphrase)` |
| 51 | 32 | Payment ID | Raw 32 bytes |
| 83 | 8 | Commitment ID | Big-endian uint64 |
| 91 | 16 | Amount | Big-endian uint128 |
| 107 | 8 | Start time (`t0_ms`) | Big-endian uint64 ms |
| 115 | 8 | End time (`t1_ms`) | Big-endian uint64 ms |
| 123 | 8 | Pause time (`pause_ms`) | Big-endian uint64 ms |

## Merkle tree leaf hashing

Daily batches anchored to `vaeltrix_scoreboard` contain a Merkle root over all payment verdicts processed during that UTC day:

```ts
export function computeMerkleLeaf(params: {
  paymentIdHex: string;
  verdict: "OnTime" | "LateCompletion" | "NoCompletion";
  latencyMs: bigint;
}): Buffer {
  const payload = Buffer.concat([
    Buffer.from(params.paymentIdHex, "hex"),
    Buffer.from(params.verdict, "ascii"),
    Buffer.from(params.latencyMs.toString(), "ascii"),
  ]);
  return createHash("sha256").update(payload).digest();
}
```

## Error handling

The SDK wraps raw Soroban simulation errors into structured `VaeltrixError` instances, providing clear diagnostic messages:

```ts
export function handleContractError(error: unknown): string {
  if (error instanceof VaeltrixError) {
    switch (error.errorName) {
      case "InsufficientStake":
        return "Provider does not have enough unreserved stake to cover this volume.";
      case "NotCovered":
        return "Payment initiation timestamp falls outside the active commitment coverage window.";
      case "OutOfScope":
        return "Payment parameters (asset, amount, or corridor) do not match the SLA template scope.";
      default:
        return `Contract error (${error.code}): ${error.message}`;
    }
  }
  return error instanceof Error ? error.message : "Unknown transaction error";
}
```
