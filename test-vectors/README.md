# Shared test vectors

Shared by the Rust and TypeScript suites so on-chain and off-chain logic can never drift (guide §4.6). CI's `vectors` job fails if either side disagrees with these files.

| File | Consumed by | Filled by |
| --- | --- | --- |
| `verdict.json` | `crates/vaeltrix-verdict/tests/vectors.rs`, `packages/core/test/vectors.test.ts` | VX-105 (≥ 40 cases) |
| `ids.json` | `crates/vaeltrix-types/tests/vectors.rs`, `packages/core/test/vectors.test.ts` | VX-105 (≥ 5 cases) |
| `receipts.json` | `crates/vaeltrix-verdict/tests/vectors.rs`, `packages/core/test/vectors.test.ts` | VX-105 (≥ 3 cases, §4.4 layout) |

Each file is a JSON array of objects. Case shape (from §4.6):

```json
{ "name": "late by one ms past grace", "fn": "evaluate",
  "input": { "t0_ms": 1760000000000, "t1_ms": 1760003720001, "now_ms": 1760010000000,
             "target_ms": 3600000, "grace_ms": 120000, "pause_ms": 0 },
  "expect": { "verdict": "Late", "latency_ms": 3720001 } }
```

Integers that can exceed 2^53 (amounts, i128) are written as decimal strings.

## VX-105 fixture contract

Each data file validates against the adjacent Draft-07 `*.schema.json`. The
TypeScript vector suite checks the schemas, unique names, ID hashing, receipt
field offsets, deterministic signatures, and rejection of tampered messages.
The Rust suites load the same JSON. Production function dispatch remains in
VX-103, VX-104 and VX-106; passing today's integrity checks does not establish
that those implementations exist or agree yet.

- Verdicts use the guide's `{name, fn, input, expect}` shape. `null` means `None`
  (invalid input or checked arithmetic overflow). Scalar results are scalar
  `expect` values; split results name all three tuple components.
- Amounts are decimal strings. Times within JavaScript's safe integer range use
  JSON integers; larger u64 values use decimal strings. Consumers must convert
  times and amounts directly to integers/bigint, without passing large strings
  through `Number`.
- Carve-out spans use `{kind, from_ms, to_ms}` and results use
  `{pause_ms, out_of_scope}`. Intervals are half-open; overlapping pauses count
  once. `InvalidBeneficiary` excludes the payment and contributes no pause.
  A pause greater than elapsed completion time yields `null`. These fixture conventions resolve details left unspecified in §4.5; they
  do not add or change production types.
- ID cases contain the full `admin_scaddress_xdr` bytes, including the SCAddress
  discriminant and, for account addresses, the PublicKey discriminant. Both
  account and contract admins and UTF-8 transaction IDs are represented.
- Receipt seeds are deliberately public test fixtures (`00..1f`), never funded,
  registered, or used for deployment. Signatures are over the 131 bytes directly,
  without pre-hashing. All messages use the testnet network ID. Large amount and
  u64 fields catch truncation and little-endian mistakes.

## Coverage and independent hand checks

Expected values were generated by a throwaway Python script using integer
arithmetic, `hashlib`, `struct` and `cryptography` Ed25519. Node's native crypto
independently checks hashing and signatures in the committed test suite.

46 verdict cases cover every §4.6 checklist item, plus deadline/cooldown overflow,
zero daily cap, adjacent spans and u64 boundaries. Five manual arithmetic checks:

| Case | Calculation | Expected |
| --- | --- | --- |
| Exactly on target plus grace | 2,100 − 1,000 = 1,000 + 100 | OnTime, latency 1,100 ms |
| One ms over grace | 2,101 − 1,000 = 1,101 > 1,100 | Late, latency 1,101 ms |
| Fractional stroops round down | floor(19,999 × 50 / 10,000) | 99 stroops |
| Spec minimum stake | max(10,000,000,000, 3 × 1,000,000,000,000 × 50 / 10,000) | 15,000,000,000 stroops (1,500 USDC) |
| Odd bond, three observers | provider floor(101 / 2) = 50; floor(51 / 3) = 17 each | (50, 17, 0) |

For the five-observer split, the same 51-stroop remainder gives 10 each and one
stroop of dust to the provider; the provider receives 50 + 1 in total.
